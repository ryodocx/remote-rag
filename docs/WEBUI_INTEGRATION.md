# Web UI Integration Guide

This document explains how to integrate the RRAG MCP Server with browser-based AI Chat Web UIs, such as ChatGPT, Claude, Gemini, and Copilot.

---

## 1. Conclusion: Native MCP Support

As of 2026, the **Model Context Protocol (MCP)** is highly optimized for **local desktop applications** (such as Claude Desktop, Cursor, Windsurf, Zed).

Therefore, **standard browser-based Web UIs (ChatGPT, Claude Web, Gemini Web) do not provide a built-in feature to register or connect directly to an arbitrary MCP server.**

If you want to use the high-precision RAG search from a Web UI, you must expose the search interface as a **REST API (OpenAPI)** instead of the raw MCP protocol, and use the platform's external API integration features as a workaround.

---

## 2. Workarounds for Web UI Integration

Below are the workarounds tailored to each platform.

### A. ChatGPT (Custom GPTs / Actions)

Integration is possible using the **Custom GPTs "Actions"** feature available to ChatGPT Plus / Team / Enterprise users.

1. **Create a REST API Wrapper**
   The current `FastMCP` communicates via JSON-RPC, which ChatGPT cannot call directly. Create a simple FastAPI REST endpoint that wraps the `WikiSearcher` class from `searcher.py`.
2. **Publish the OpenAPI Schema**
   Export the `/openapi.json` generated by FastAPI and import it into the Custom GPT's Actions configuration.
3. **Configure Authentication**
   In the Actions settings, set `Authentication` to `OAuth`. Provide the Client ID, Secret, and Authorization URL of your IdP (e.g., Okta). When users interact with the GPT, they will be prompted to log in, and the resulting Bearer token will pass securely through the `auth-helper` proxy.

### B. Microsoft Copilot (Copilot Studio)

You can integrate via **Copilot Studio** in enterprise environments.

1. Prepare the REST API (OpenAPI Schema) as described for ChatGPT.
2. In Copilot Studio, go to "Custom Copilots" and "Add an Action" to import the OpenAPI schema as a plugin.
3. Combine this with Entra ID OAuth authentication to restrict search access only to authorized internal users.

### C. Claude Web / Gemini Web

Currently, the consumer Web versions of Claude and Gemini do not offer a GUI feature (like Custom GPTs) for users to seamlessly add arbitrary OpenAPI endpoints with a single click. *(Note: Tool Use via their developer APIs is possible, but independent of the browser chat UI).*

**Recommended Solution:**
If you want to combine powerful models (Claude/Gemini) with this RAG system in a browser interface, deploy an open-source chat UI framework such as **Dify**, **LangFlow**, **Streamlit**, or **Chatbot UI**. Then, integrate this system's REST API as a custom tool within that framework.

---

## 3. Future Outlook (MCP-to-OpenAPI Bridge)

The open-source community is actively developing "MCP-to-OpenAPI Bridges" that automatically convert existing MCP servers into OpenAPI-compliant REST APIs. In the future, you may be able to wrap this project's MCP server with a bridge tool and integrate it with ChatGPT (Custom GPTs) without writing any code.

Additionally, if AI platforms (OpenAI, Google, Anthropic) officially adopt MCP in their Web UIs in the future, integration will be as simple as pasting the endpoint URL into the settings screen.

For now, the most seamless and robust experience remains with **native MCP-supported desktop apps** like Claude Desktop and Cursor.
